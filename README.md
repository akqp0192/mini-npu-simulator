# Mini NPU Simulator

## 실행 방법
`main.py`, `data.json`, `README.md`를 같은 폴더에 둔 뒤 터미널에서 `python main.py`를 실행합니다.
- `1`: 3x3 사용자 입력 모드
- `2`: data.json 분석 모드
- `0`: 종료

## 구현 요약
- 라벨 정규화: `+`, `cross`는 `Cross`; `x`는 `X`로 표준화합니다.
- MAC: 중첩 for문으로 같은 위치의 값을 곱하고 누적합니다. NumPy 등 벡터화 라이브러리는 사용하지 않습니다.
- 동점: `abs(score_cross - score_x) < 1e-9`이면 `UNDECIDED`입니다.
- 사용자 입력: 행마다 숫자 개수와 숫자 변환을 검증하고 오류 시 재입력합니다.
- JSON: 패턴 키, 필수 항목, 라벨, 행렬 크기와 숫자 형식을 케이스별로 검증합니다. 잘못된 케이스는 FAIL 처리하고 다음 케이스를 계속합니다.

## 결과 리포트 및 실패 원인 분석
- 패턴 키가 `size_N_식별자` 규칙과 다르면 크기를 추출할 수 없어 FAIL 처리됩니다.
- filters 또는 patterns가 객체 형태가 아니면 JSON 스키마 오류로 처리됩니다.
- 필터나 패턴의 행/열 개수가 N과 다르면 크기 불일치로 처리됩니다.
- 행렬 원소가 숫자가 아니거나 무한대/NaN이면 유효하지 않은 데이터로 처리됩니다.
- expected 값이 `+`, `cross`, `x` 중 하나가 아니면 라벨 오류입니다.
- 계산 결과가 expected와 다르면 판정 불일치로 FAIL 처리됩니다.
- 두 점수의 차이가 epsilon보다 작으면 UNDECIDED로 판정합니다.
- UNDECIDED는 Cross 또는 X expected와 일치하지 않으므로 해당 테스트는 FAIL입니다.
- FAIL 목록에는 케이스 식별자와 실패 원인을 함께 출력합니다.
- 모든 테스트가 PASS라면 데이터 라벨과 판정 정책이 테스트 기대값에 부합한 것입니다.
- 제공 예시 JSON은 5x5, 13x13, 25x25 크기의 Cross/X 기본 패턴을 포함합니다. 실제 수업 제공 파일이 있으면 교체해 검증해야 합니다.

## 시간 복잡도 분석
- N x N 행렬에서 바깥 반복문은 N회, 안쪽 반복문은 행마다 N회 실행됩니다.
- 따라서 MAC의 곱셈 및 누적 연산 횟수는 N x N = N²회입니다.
- MAC 연산의 시간 복잡도는 O(N²)입니다.
- 입력 행렬을 제외한 MAC 함수의 추가 공간 사용량은 누적 점수 변수뿐이므로 O(1)입니다.
- 성능 측정은 3x3, 5x5, 13x13, 25x25 크기별로 수행합니다.
- 각 크기에서 MAC 함수 호출 구간만 10회 측정하고 평균 시간을 ms로 출력합니다.
- 표에는 행렬 크기, 평균 시간(ms), N² 연산 횟수가 포함됩니다.
- N이 증가하면 연산 횟수는 제곱에 비례해 증가합니다.
- 실제 시간은 CPU 성능, Python 실행 환경, 측정 오버헤드의 영향을 받습니다.
- 작은 행렬에서는 시간 측정 오버헤드가 상대적으로 크게 나타날 수 있습니다.
- 따라서 반복 측정 평균과 N² 증가 추세를 함께 해석해야 합니다.

## 성능 측정 기준
- 크기: 3x3, 5x5, 13x13, 25x25
- 반복: 크기별 10회
- 단위: ms
- 측정 구간: MAC 함수 호출 구간
