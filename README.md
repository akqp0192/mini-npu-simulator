# Mini NPU Simulator

Python으로 MAC(Multiply-Accumulate) 연산을 수행하고, Cross/X 필터와 입력 패턴의 점수를 비교해 패턴을 분류하는 간단한 NPU 시뮬레이터입니다.

## 1. 실행 환경

- 언어: Python 3
- 개발 도구: Visual Studio Code
- 사용 모듈: `json`, `os`, `re`, `time`, `math` (Python 표준 라이브러리)

외부 패키지 설치 없이 실행할 수 있습니다.

## 4. 주요 구현 내용

### 4-1. MAC 연산

`mac(pattern, filter_matrix)` 함수에서 중첩 `for`문을 사용합니다. 입력 패턴과 필터의 같은 위치에 있는 값을 곱한 뒤 누적하여 MAC 점수를 계산합니다.

### 4-2. 패턴 분류

`classify()` 함수에서 Cross 필터 점수와 X 필터 점수를 비교합니다.

- Cross 점수가 더 크면 `Cross`
- X 점수가 더 크면 `X`
- 두 점수의 차이의 절댓값이 `EPSILON(1e-9)`보다 작으면 `UNDECIDED`

### 4-3. 입력 및 JSON 데이터 검증

- 사용자 입력 시 행마다 입력한 숫자의 개수와 숫자 형식을 확인합니다.
- JSON 분석 시 필터와 패턴의 존재 여부, 행렬 크기, 원소의 숫자 형식, expected 라벨을 확인합니다.
- 각 테스트 결과를 expected 값과 비교해 `PASS` 또는 `FAIL`로 표시합니다.
- 실패 케이스는 식별자와 실패 원인을 별도로 출력합니다.

## 5. 테스트 결과 및 실패 원인 분석

현재 저장소의 예제 데이터는 총 8개 테스트 케이스로 구성되어 있습니다.

| 테스트 크기 | 케이스 수 |
|---|---:|
| 5×5 | 2 |
| 13×13 | 3 |
| 25×25 | 3 |
| **합계** | **8** |

첨부한 JSON 분석 실행 화면에서는 다음 결과를 확인했습니다.

- 전체 테스트: 8개
- PASS: 7개
- FAIL: 1개
- 실패 케이스: `size_13_3`

`size_13_3`은 동점 처리 동작을 확인하기 위해 모든 원소가 0인 패턴으로 구성한 예제입니다. 따라서 Cross 점수와 X 점수가 모두 0으로 같아 `UNDECIDED`가 반환됩니다. expected 값은 `X`이므로 테스트 결과는 FAIL입니다.

이 FAIL은 계산 오류가 아니라, 점수가 같은 경우 어느 한쪽으로 임의 분류하지 않고 `UNDECIDED`로 처리하는 규칙을 확인하기 위한 의도적인 테스트입니다.

그 밖에 발생할 수 있는 실패 원인은 다음과 같습니다.

1. **패턴 키 형식 오류**: 케이스 키가 `size_N_식별자` 형식이 아닌 경우
2. **필터 누락**: 해당 크기의 Cross 또는 X 필터가 없는 경우
3. **행렬 크기 불일치**: 패턴 또는 필터의 행·열 개수가 지정된 크기와 다른 경우
4. **데이터 형식 오류**: 행렬 원소가 숫자가 아니거나 유효하지 않은 값인 경우
5. **라벨 오류**: expected 값이 `+`, `cross`, `x` 중 하나가 아닌 경우
6. **판정 불일치**: 실제 판정 결과와 expected 값이 다른 경우
7. **동점 판정**: 두 점수의 차이가 EPSILON보다 작아 `UNDECIDED`가 반환된 경우

## 6. 시간 복잡도 분석

N×N 행렬을 처리하는 MAC 연산은 다음과 같이 동작합니다.

- 바깥쪽 반복문: N회
- 안쪽 반복문: 각 바깥 반복마다 N회
- 전체 곱셈 및 누적 횟수: N×N = N²

따라서 MAC 연산의 시간 복잡도는 **O(N²)**입니다. 입력 행렬을 제외한 MAC 함수 내부의 추가 공간은 누적 점수를 저장하는 변수 정도이므로 **O(1)**입니다.

- 측정 크기: 3×3, 5×5, 13×13, 25×25

## 9. 대규모 행렬(1000×1000) 처리 시 시간·메모리 고려

현재 구현은 Python의 중첩 리스트와 일반 `for`문으로 MAC 연산을 수행합니다. 따라서 행렬 크기 N이 커지면 연산량은 N²에 비례해 증가합니다.

### 9-1. 연산량 추정

- 25×25 행렬의 MAC 연산량: 625회
- 1000×1000 행렬의 MAC 연산량: 1,000,000회
- 25×25와 비교하면 한 번의 MAC 연산량은 1,600배입니다.
- Cross와 X 필터를 각각 한 번씩 계산하므로, 패턴 1개를 분류할 때는 총 약 2,000,000회의 원소 곱셈·누적이 수행됩니다.

이는 연산 횟수에 따른 이론적 비교입니다. 현재 성능 측정은 최대 25×25까지만 수행했으므로, 1000×1000의 실제 실행 시간은 측정하지 않았습니다. 단순히 작은 행렬의 측정 시간을 1,600배 하는 방식은 Python 실행 오버헤드, 캐시, 메모리 접근 패턴 등의 영향 때문에 실제 시간과 다를 수 있습니다.

### 9-2. 메모리 사용량 추정

현재 코드처럼 Python의 `list[list[float]]` 구조로 1000×1000 행렬 하나를 저장한다고 가정하면, 원소 참조와 Python float 객체만 대략 32MB 수준이 될 수 있습니다. 이는 64비트 CPython에서 포인터 약 8바이트와 float 객체 약 24바이트를 가정한 근사치이며, 리스트·행 객체 등의 부가 비용은 별도입니다.

입력 패턴 1개와 Cross/X 필터 2개, 총 3개 행렬을 동시에 보유하면 이 단순 추정만으로 약 96MB가 필요합니다. JSON 파싱 과정의 객체, 테스트 데이터, 인터프리터 및 기타 변수의 메모리도 추가되므로 실제 프로세스 메모리는 더 커질 수 있습니다. 실제 사용량은 Python 구현, 값의 자료형 및 데이터 구조에 따라 달라집니다.

### 9-3. 우선순위별 최적화 방안

1. **메모리 레이아웃 개선**: 중첩 Python 리스트 대신 연속된 메모리 영역을 사용하는 배열 자료구조(예: 고정 폭 숫자 배열 또는 NumPy 배열)를 사용합니다. 객체와 포인터 오버헤드를 줄이고 캐시 지역성을 높일 수 있습니다.
2. **블로킹(타일링)**: 행렬을 작은 블록 단위로 나누어 처리합니다. 필요한 데이터 블록을 캐시에 재사용하도록 해 대규모 행렬에서 메모리 접근 비용을 줄이는 데 도움이 됩니다.
3. **불필요한 데이터 복사 및 동시 보유 최소화**: 입력과 필터를 중복 복사하지 않고, 처리 후 더 이상 필요하지 않은 큰 객체를 해제합니다. JSON 전체를 한 번에 메모리에 올리는 방식도 데이터 규모에 따라 스트리밍 또는 단계적 로딩을 검토합니다.
4. **벡터화 및 하드웨어 가속**: 검증된 배열 연산 라이브러리의 벡터화 연산을 사용하고, 필요하면 SIMD 또는 GPU 가속을 검토합니다. 단, 데이터 이동 및 초기화 비용까지 포함해 실제 성능을 측정해야 합니다.
5. **병렬 처리**: 독립적인 패턴 케이스를 여러 작업으로 나누어 병렬 실행할 수 있습니다. 다만 Python의 실행 모델, 프로세스 간 데이터 복사 및 메모리 대역폭 경쟁을 고려해야 합니다.

우선 적용할 항목은 메모리 레이아웃 개선과 블로킹입니다. 그다음 데이터 복사 최소화와 벡터화를 적용하고, 실제 측정에서 병렬화가 유리한 경우에 병렬 처리를 검토하는 것이 합리적입니다.

## 10. CPU와 병렬 NPU의 병목 비교

현재 프로그램의 MAC 함수는 CPU에서 중첩 `for`문을 순서대로 실행하는 직렬 구현입니다. 한 번의 MAC 연산에서 각 원소의 곱셈과 누적이 순차적으로 처리되므로, 행렬 크기가 커질수록 반복문 실행 및 메모리 접근 비용이 증가합니다.

| 구분 | CPU 직렬 처리(현재 구현) | 병렬 NPU 처리(개념적 비교) |
|---|---|---|
| 연산 방식 | 소수의 실행 코어가 명령을 순서대로 처리 | 다수의 연산 유닛이 여러 원소 연산을 동시에 처리 |
| 주요 병목 | Python 반복문 오버헤드, 연산 처리량, 캐시 및 메모리 접근 | 메모리 대역폭, 데이터 공급, 연산 유닛 활용률, 데이터 이동 |
| 대규모 MAC | N²개의 원소 연산을 순차적으로 수행 | 독립적인 원소 곱셈을 병렬화하고 부분합을 결합할 수 있음 |
| 주의점 | 큰 행렬에서 실행 시간이 길어질 수 있음 | 데이터 전송·배치·동기화 비용이 커지면 병렬 처리 이점이 감소 |

### 10-1. CPU 직렬 처리의 한계

현재 `mac()` 함수는 두 개의 중첩 반복문으로 모든 행렬 원소를 차례로 방문합니다. 따라서 N×N 행렬에서 N²번의 곱셈과 누적이 발생합니다. Python 인터프리터의 반복문 실행 비용도 더해지므로, 1000×1000처럼 큰 행렬에서는 연산량 증가가 실행 시간에 직접적인 부담이 됩니다.

### 10-2. 병렬 NPU의 병목

NPU는 다수의 곱셈 누산 유닛을 이용해 독립적인 MAC 연산을 병렬로 수행하도록 설계할 수 있습니다. 하지만 연산 유닛을 늘리는 것만으로 성능이 계속 증가하지는 않습니다.

- **메모리 대역폭 병목**: 연산 유닛이 처리할 데이터를 메모리에서 충분히 빠르게 공급하지 못하면 유닛이 대기합니다.
- **데이터 이동 병목**: 호스트 CPU와 가속기 사이의 데이터 전송 및 장치 메모리 적재 시간이 연산 시간보다 커질 수 있습니다.
- **병렬 효율 저하**: 작업 크기가 작거나 분할·동기화 비용이 크면 병렬화로 얻는 이득이 줄어듭니다.
- **누적 및 데이터 재사용**: 부분합을 결합하고 입력·필터 데이터를 재사용하는 방식이 비효율적이면 메모리 접근량이 증가합니다.

### 10-3. 대규모 MAC에서의 핵심 병목과 대응

대규모 MAC에서는 단순 연산 횟수뿐 아니라 데이터를 얼마나 효율적으로 공급하고 재사용하는지가 중요합니다. CPU에서는 직렬 반복문과 메모리 접근이 부담이 되고, 병렬 NPU에서는 연산 유닛에 데이터를 공급하는 메모리 대역폭과 데이터 이동이 주요 병목이 될 수 있습니다.

따라서 연속 메모리 레이아웃과 블로킹으로 데이터 지역성을 높이고, 필터와 입력 데이터를 재사용하며, 실제 장치에서 연산 시간과 데이터 전송 시간을 분리해 측정해야 합니다. 이 프로젝트는 CPU 직렬 구현을 대상으로 하며, NPU 비교는 병렬 하드웨어의 일반적인 구조에 기반한 개념적 분석입니다. 실제 NPU에서의 성능 수치를 측정한 것은 아닙니다.
